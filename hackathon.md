### 2026-09-27 - Repaired the `rank login` browser exchange end to end and moved the app onto rank.listeningkit.com — matthewdonsemail-lab
- Beads: n/a
- Commit: uncommitted
- Files: apps/web/src/pages/cli.tsx, apps/web/src/pages/onboarding/OnboardingSplit.tsx, apps/web/src/pages/onboarding/OnboardingAuth.tsx, apps/web/src/index.css, packages/rank-cli/src/cli/commands/login.ts, packages/rank-cli/src/cli/commands/login.test.ts, convex/auth.config.ts, hackathon.md
- Five stacked defects, each hiding the next. (1) `CliLoginPage` called `useCallback` after `if (!isLoaded) return`, so the hook count went 6 to 7 the moment Clerk finished loading and React threw #310, "Rendered more hooks than during the previous render" — not the update loop commit 2a81248 had been chasing. Confirmed by reading the minified production bundle `index-Bs9rasBs.js` off `rank-web-gray.vercel.app`, which contained `!e)return $.jsx(wle,{}); const p=F.useCallback(...)`. (2) `/cli` had its own one-off shell; the two-panel auth chrome is now `OnboardingSplit`, mounted by sign-in, sign-up and `/cli`, so they cannot drift, and its controls come from the same `splitControl` recipes as Clerk's appearance map. (3) The UA stylesheet's `code { font-family: monospace }` beats inheritance, so the inline `rank` / `rank login` commands rendered in a monospace face; `code/kbd/samp/pre` now inherit, which also enforces the brand rule. (4) On Windows the CLI opened the browser via `cmd /c start "" <url>`; cmd re-parses the joined command line and `&` is its statement separator, so the browser received only `?state=<state>` and the CLI waited forever for an exchange the page could not make. Now `rundll32.exe url.dll,FileProtocolHandler`, which takes the URL as a discrete argv entry. (5) The page rendered "Authorized" as soon as the loopback POST landed, then the CLI died with `NoAuthProvider`, so the browser claimed success while the terminal printed failure.
- The real cause of (5) was an issuer mismatch. A Clerk token is only valid for the instance that minted it, and the three parties disagreed: the production web build signs with `internal-piglet-2301`, the local build with `up-shiner-8211`, and Convex trusted only `stirring-gator-5763`. `CLERK_JWT_ISSUER` now accepts a comma-separated list and `convex/auth.config.ts` maps it to one provider per issuer; all three are registered on `perceptive-cow-413` and `blissful-meerkat-319`. Verified per issuer by presenting a forged token: the response moved from `NoAuthProvider` to `AuthProviderDiscoveryFailed`, which is what a bad signature against a now-resolved provider looks like. Production Convex had never been provisioned (`FIRECRAWL_API_KEY` and the TypeSafe keys were absent, so no push could complete) and those were copied from dev.
- `runExchangeServer` gained a `verifyToken` awaited before the server answers `ok`, so a success the browser renders as "Authorized" means the deployment actually accepted the session. A rejection answers 401 and deliberately leaves the one-shot listener open, so the visitor can sign in again and retry on the same run; the page treats 401 as retryable and keeps its session mirror. The exchange window went 120s to 300s to outlast a Clerk round trip. Covered by a new test asserting 401-then-retry.
- `/cli` is now gated: entered without a valid access code there is nothing to authorize, so the visitor is sent back to sign in / sign up rather than parked on a dead end, with both offered as buttons for when the automatic hop is blocked. The sign-in hand-off returns to the full authorize query instead of a bare `/cli`, so the exchange round-trips on the URL as well as through the session mirror.
- `rank.listeningkit.com` is live (A record to Vercel, serving the current bundle) and is now `DEFAULT_WEB_URL` for the CLI, replacing `https://rank-web-gray.vercel.app`. This corrects the earlier log entry below that recorded the subdomain as NXDOMAIN, and the OAuth callback redirect URIs that still need registering on the Clerk dashboard are now the `https://rank.listeningkit.com/oauth/sso-callback` and `https://rank.listeningkit.com/oauth/sign-up/sso-callback` pair.

New pure helpers in `lib/firecrawl/crawl/helpers`: `summarizePage` (title, description, and an excerpt of real prose with links, images, headings marks, menus and cookie lines removed) and `mapWithConcurrency` (ordered results, a concurrency cap, and one failing item cannot stop the batch). `candidateDocument` now feeds the reranker the page title, description and excerpt, cut to 1200 characters. ### 2026-09-25 - real Nebius rerank client (Mandeep)
Replaced the placeholder in `lib/nebius/rerank/client.ts` (it scored candidates 1/(index+1) and ignored the query) with a client for Nebius Token Factory `POST https://api.tokenfactory.nebius.com/v1/rerank`, taken from Nebius's own OpenAPI spec. The old default base URL (`api.studio.nebius.ai`) and the `BAAI/bge-reranker-v2-m3` default were not what Nebius documents; the default model is now `Qwen/Qwen3-Reranker-8B`, the one in the spec, and `DEFAULT_RANK_MODEL` overrides it. The client maps scores back onto candidates by index, sorts best first, applies `topK`, validates every field it uses, retries 408/429/5xx and network failures, and raises `NebiusError` with plain-language messages that never include the key or the response body. It throws without `NEBIUS_API_KEY` instead of returning an unranked list. The old behaviour is kept only as `baselineRank`, clearly labelled as not a relevance model. `rerankDetailed()` also returns the model and token usage. 11 vitest tests with a fake fetch, not yet run against the live API (no Nebius key set). Updated README, features, self-hosting, agent tools and naming docs to say exactly that.
